Audit of the repository against the methodology diagram (human survey → digital personas → persona-conditioned generation with an unconditioned control → SSR → validation on held-out human data, with a development split and a frozen test split). Every status below is based on code and data in the repository; numbers come from `data/validation/methodology_metrics.json` (generated by `scripts/dp_methodology_eval.py`).

## 2. Evidence by stage

**Stage 1.** The raw Google-Forms export (`data/Capstone_Reviews(Responses).xlsx`) has **215** rows and contains no names, e-mail addresses or phone numbers (only a timestamp, which the cleaned file drops; respondents are `HS001…HS215`). Consent (Q1) and age (Q2/Q3) answers are present, so filtering is reproducible:

| Step | Count |
|---|---|
| Raw submissions | 215 |
| No consent | −4 |
| Recorded age under 18 | −6 |
| Not a smartphone owner | −1 |
| **Initially eligible** | **204** |
| Unresolved age eligibility (Q2 blank ×3, Q2 contradicts age ×1) | −4 |
| **Primary analysis cohort** | **200** |

The diagram's **N = 203 is not what the data supports under the documented rules**. 203 would result only if the three blank-Q2 respondents were reinstated (no approved protocol in the repository authorises that). Consent decisions are the respondents' recorded Q1 answers; the consent wording and any ethics approval are not in the repository and cannot be verified here.

**Stage 2.** Four personas (P1 premium tier, P2 mid-range heavy user, P3 mid-range moderate user, P4 budget/undisclosed) are assigned by a deterministic rule on two survey answers (price paid, daily use); `assign_persona` reproduces all 200 saved assignments. Persona cards hold aggregate statistics and Q23–Q25 theme shares only; no respondent IDs or free text. Respondent specs are sampled from each persona's observed answers (seeded, independent per attribute). Q21 and Q26 are excluded from persona profiles and prompts. The personas are descriptive segments, not statistically derived clusters.

**Stage 3.** Persona prompts contain the sampled profile (`profile_text_v1/v2`) and the question; the system instruction requests words only and no ratings. **No unconditioned control existed before this audit.** `scripts/pilot_generate_condition.py` now generates a `control` condition (same system instruction and question, no persona information) and a `persona` condition into separate folders (`data/pilot_<provider>_<condition>_<task>/`) with prompts, raw responses, failures, configuration and canonical-SSR scores.

**Stage 4.** SSR uses the unmodified canonical functions (ε = 0, T = 1; hash of `canonical_ssr.py` and of the anchor file equal the values recorded at Step 6). Deviations: one approved anchor set per construct (the paper's six sets are unavailable), local encoders instead of `text-embedding-3-small`, and Q21 as a proxy for the Behavioral Intention construct. Questions without a compatible approved anchor set are reported as unrated. The `k = 3` setting belongs to the legacy kNN in `agent.py` and is untouched.

**Stage 5.** Metric implementations and held-out results (test half, n = 97, encoder `local_bge_base` selected on the dev half; SSR on each respondent's own Q26 text vs the same respondent's Q21):

| Metric | Implementation | Result |
|---|---|---|
| Exact accuracy (PMF argmax = Q21) | `ssr_eval_lib.metrics_vs_q21`, `dp_methodology_eval.paired_metrics` | 0.351 (majority-class baseline 0.351) |
| MAE (E[r] vs Q21) | same | 0.861 (mean-predictor baseline 0.901) |
| Spearman ρ | same | 0.297, bootstrap 95% CI 0.094–0.476 |
| Pearson r | `dp_methodology_eval.paired_metrics` (new) | 0.327 |
| Cohen's κ (argmax vs Q21, labels 1–5) | `dp_methodology_eval.kappa` (new) | quadratic-weighted 0.343; linear 0.225; unweighted 0.112 |
| JSD (mean SSR PMF vs Q21 distribution, log base 2) | `dp_methodology_eval.jsd` (new) | 0.019 |
| KS (synthetic vs human-text E[r], per persona) | `dp_validation_agent.distribution_comparison`, `dp_methodology_eval.run` | P1 0.63, P2 0.50 (descriptive; 10 synthetic responses each; test-half humans 30 / 20) |
| TSTR | `dp_methodology_eval.tstr` (new; prerequisite checks) | **unavailable**: synthetic labels would be SSR-derived (circular) and the 20 saved synthetic responses fall into only two SSR classes (19 / 1) |

Undefined metrics (constant predictions, single class, too few pairs) are returned as `unavailable` with a reason, never as 0.

## 3. Development / test split and leakage audit

- The dev/test split (97/97, stratified by Q21, seed 20261028) existed only as an in-memory recomputation. It is now written once to `data/validation_split/frozen_split_manifest.json` (respondent IDs and SHA-256). Later runs verify it and stop if it differs. Its membership is identical to the split behind all earlier reported results.
- No respondent appears in both halves and there are no duplicate respondent IDs. Four very short answers ("yes", "no", "good", "yess") occur verbatim in both halves; this is identical input text, not a shared respondent.
- The encoder was selected on the dev half only. Anchors are a pre-approved file with an unchanged hash; there is no evidence that anchors were tuned on data.
- **Residual leakage risk:** personas and their Q23–Q25 theme summaries were built from the whole primary cohort, including test-half respondents (their Q21 and Q26 were never used). Whether prompts were ever adjusted after seeing test metrics cannot be verified from the repository history.

## 4. Live generation check (local Ollama, `qwen2.5:0.5b`, Q26 question)

| Condition | Generated | Passed quality checks and scored | Expected ratings |
|---|---|---|---|
| Persona-conditioned (one profile per persona) | 4 | 3 | 2.73, 3.49, 3.51 |
| Unconditioned control | 4 | 4 | 4.06, 3.22, 3.30, 2.76 |

Every scored PMF sums to 1. With four responses per condition this is a functioning pipeline check, not evidence of a difference between conditions.

## 5. Limitations and manual actions

1. Confirm whether the protocol allows reinstating the three blank-Q2 respondents (200 → 203) and record that decision; do not change the count without it.
2. Add the consent wording and ethics approval to the repository if they exist.
3. A meaningful persona-vs-control comparison needs many more responses per condition (and ideally a stronger model than 0.5B parameters).
4. TSTR needs synthetic data with labels that are independent of SSR (e.g. a synthetic Likert answer collected by a separate, validated procedure) and enough examples per class.
5. The human↔synthetic comparison is unpaired and covers P1/P2 only for the saved Gemini pilot.
